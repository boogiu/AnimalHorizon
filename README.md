# DirectX 11 3D 생활형 게임 모작 프로젝트

DirectX 11을 활용하여 3D 생활형 게임 「동물의 숲」 스타일의 시스템과 렌더링 구조를 모작한 1인 개발 프로젝트입니다.

본 프로젝트는 단순한 게임 콘텐츠 구현보다, 게임 클라이언트 개발에 필요한 기반 구조를 직접 설계하는 것을 목표로 했습니다.
게임 오브젝트 프레임워크, 렌더링 파이프라인, 리소스 변환 파이프라인, 데이터 기반 오브젝트 생성, NPC 상호작용, 맵 제작 툴, 애니메이션 시스템 등을 직접 구현했습니다.

## 솔루션 구조

본 프로젝트는 `Engine`을 모든 실행/툴 프로젝트의 공통 기반 계층으로 두고, `Client`, `MapEditor`, `ModelLoader`가 각각 `Engine`을 참조하는 구조입니다.

```text
Solution
├─ Engine
│  └─ 공통 엔진 계층
│     ├─ 게임 오브젝트 / 컴포넌트 / 트랜스폼
│     ├─ 렌더링 파이프라인
│     ├─ 리소스 객체 및 리소스 관리 구조
│     ├─ 충돌 / 애니메이션 / UI
│     └─ ImGui 디버그 기반 구조
│
├─ Client
│  └─ 실제 게임 실행 프로젝트
│     └─ Engine 의존
│
├─ MapEditor
│  └─ 맵 제작 툴 프로젝트
│     └─ Engine 의존
│
└─ ModelLoader
   └─ 외부 리소스를 엔진 친화적 바이너리 포맷으로 변환하는 툴 프로젝트
      └─ Engine 의존
```

### 의존 관계

```text
Engine
├─ Client
├─ MapEditor
└─ ModelLoader
```

`Engine`은 공통 기반 시스템을 제공하고, 나머지 프로젝트들은 각각의 목적에 맞게 `Engine`의 구조를 활용합니다.

* `Client`는 `Engine`을 기반으로 실제 게임 콘텐츠와 런타임 로직을 실행합니다.
* `MapEditor`는 `Engine`의 오브젝트, 충돌, 렌더링 구조를 활용하여 맵 제작 기능을 제공합니다.
* `ModelLoader`는 `Engine`의 리소스 객체 체계를 기반으로 외부 모델 데이터를 엔진에서 사용하기 쉬운 바이너리 리소스로 변환합니다.

## 프로젝트별 역할

### Engine

`Engine`은 프로젝트 전체에서 공통으로 사용하는 기반 시스템을 담당합니다.

`Client`, `MapEditor`, `ModelLoader`는 모두 `Engine`을 참조하며, 각 프로젝트는 `Engine`에서 제공하는 오브젝트 구조, 리소스 객체, 렌더링 파이프라인, 충돌, 애니메이션, UI 기반 시스템을 목적에 맞게 사용합니다.

주요 구현 내용은 다음과 같습니다.

* 게임 오브젝트 / 컴포넌트 구조
* 2D / 3D 트랜스폼 계층 구조
* 데이터 기반 오브젝트 생성 구조
* 렌더링 패킷
* DirectX 11 렌더링 파이프라인
* 디퍼드 렌더링 파이프라인
* 셰이더 / 머티리얼 / 텍스처 리소스 관리
* SRV 기반 리소스 바인딩
* 셰이더 리플렉션
* 프러스텀 컬링
* 충돌 처리
* 스키닝 애니메이션
* 애니메이션 블렌딩
* UI 렌더링
* ImGui 디버그 패널 기반 구조

---

### Client

`Client`는 실제 게임 실행 프로젝트입니다.
`Engine`의 공통 시스템을 기반으로 게임 콘텐츠 로직과 생활형 게임에 필요한 상호작용 구조를 구성합니다.

주요 구현 내용은 다음과 같습니다.

* NPC 상호작용
* 대화 시스템
* 음성 대화 기능
* 표정 상태 처리
* 행동, 소리, 이펙트 동기화
* 오토타일
* 타일별 상호작용
* 컬러 팔레트 기반 오브젝트 색상 제어
* 구름 그림자
* 둥근 지평선 렌더링 효과

---

### MapEditor

`MapEditor`는 맵 제작과 디버깅을 위한 툴 프로젝트입니다.
`Engine`의 오브젝트, 충돌, 렌더링, 리소스 구조를 활용하여 런타임과 같은 기준으로 맵 오브젝트를 배치하고 확인할 수 있도록 구성했습니다.

주요 구현 내용은 다음과 같습니다.

* ImGui 기반 맵 제작 UI
* 레이캐스트 기반 오브젝트 선택 및 배치
* 맵 오브젝트 위치, 회전, 크기 조정
* 타일 배치 및 타일 속성 확인
* 런타임 오브젝트 상태 확인
* 렌더링 리소스 및 상태 확인
* NPC 및 상호작용 오브젝트 배치 확인

---

### ModelLoader

`ModelLoader`는 외부 모델 리소스를 엔진에서 사용하기 쉬운 바이너리 포맷으로 변환하는 툴 프로젝트입니다.

이 프로젝트는 단순한 모델 확인용 뷰어가 아니라, `Engine`의 리소스 객체를 상속하거나 참조하는 구조를 기반으로 외부 파일 데이터를 엔진 친화적인 리소스 형태로 변환하는 역할을 담당합니다.

런타임에서 외부 모델 파일을 직접 파싱하는 비용을 줄이고, 엔진이 기대하는 데이터 구조에 맞춰 사전에 리소스를 변환하는 것이 목적입니다.

주요 구현 내용은 다음과 같습니다.

* 외부 모델 파일 로드
* 메시 데이터 추출
* 정점 / 인덱스 데이터 변환
* 머티리얼 데이터 변환
* 텍스처 참조 정보 정리
* 본 계층 데이터 변환
* 애니메이션 데이터 변환
* Engine 리소스 객체 체계에 맞춘 데이터 구조화
* 엔진 전용 바이너리 포맷으로 직렬화
* 변환된 바이너리 리소스를 `Client`에서 로딩할 수 있도록 구성

## 주요 시스템 설명

### 컴포넌트 패턴 기반 게임 오브젝트 구조

게임 오브젝트가 모든 기능을 직접 소유하지 않고, 기능 단위를 컴포넌트로 분리했습니다.

이를 통해 렌더링, 충돌, 애니메이션, 상호작용 등 기능을 오브젝트별로 조합할 수 있도록 구성했습니다.

```text
GameObject
├─ TransformComponent
├─ RenderComponent
├─ CollisionComponent
├─ AnimationComponent
└─ InteractionComponent
```

이 구조는 `Client`의 게임 오브젝트뿐 아니라 `MapEditor`의 오브젝트 배치 및 속성 조정 기능에서도 활용됩니다.

---

### 게임 오브젝트 계층 구조와 트랜스폼 전파

오브젝트 간 부모-자식 계층 구조를 구성하고, 부모 오브젝트의 트랜스폼 변화가 자식 오브젝트에 전파되도록 구현했습니다.

이를 통해 다음 구조를 처리했습니다.

* 3D 오브젝트의 계층적 배치
* UI 오브젝트의 2D 트랜스폼 전파
* 특정 오브젝트 기준 이펙트 부착
* 캐릭터 및 오브젝트 하위 구성 요소 위치 갱신

---

### 빌더 패턴 기반 데이터 기반 오브젝트 생성

하드코딩 방식으로 오브젝트를 직접 생성하는 구조를 줄이고, 데이터에 따라 오브젝트를 생성할 수 있는 파이프라인을 구성했습니다.

구현 목적은 다음과 같습니다.

* 오브젝트 생성 로직 중앙화
* 씬 구성 데이터와 생성 코드 분리
* 맵 제작 툴과 런타임 생성 구조 연결
* NPC, 타일, 상호작용 오브젝트 확장성 확보

---

### 렌더링 패킷 기반 렌더 데이터 처리

오브젝트가 렌더링 API를 직접 호출하지 않고, 렌더링에 필요한 데이터를 패킷 형태로 수집한 뒤 렌더러에서 일괄 처리하는 구조를 구현했습니다.

구현 목적은 다음과 같습니다.

* 게임 로직과 렌더링 제출 흐름 분리
* 렌더링 데이터 수집·정렬·제출 흐름 명확화
* 머티리얼, 셰이더, 텍스처 단위의 렌더링 제어
* 렌더링 상태 변경 최소화를 위한 기반 구조 확보

---

### Engine 리소스 객체 기반 리소스 구조

`Engine`에는 텍스처, 메시, 머티리얼, 애니메이션 등 런타임에서 사용하는 리소스 객체 체계를 구성했습니다.

`ModelLoader`는 이 리소스 객체 구조를 기준으로 외부 파일 데이터를 변환합니다.
즉, 외부 모델 데이터를 그대로 사용하는 것이 아니라, 엔진에서 바로 읽고 사용할 수 있는 형태의 바이너리 데이터로 사전 변환합니다.

이 구조의 목적은 다음과 같습니다.

* 런타임 로딩 비용 감소
* 외부 파일 포맷 의존성 감소
* 엔진 내부 리소스 구조와 데이터 포맷 통일
* Client와 Tool에서 동일한 리소스 구조 사용
* 모델, 애니메이션, 머티리얼 데이터의 일관된 관리

---

### ModelLoader 기반 바이너리 변환 파이프라인

`ModelLoader`는 외부 모델 파일을 읽어 `Engine`의 리소스 객체 구조에 맞는 바이너리 파일로 변환합니다.

변환 흐름은 다음과 같습니다.

```text
External Model File
        │
        ▼
ModelLoader
        │
        ├─ Mesh Data Extract
        ├─ Material Data Extract
        ├─ Texture Reference Extract
        ├─ Bone Hierarchy Extract
        └─ Animation Data Extract
        │
        ▼
Engine-Friendly Binary Resource
        │
        ▼
Client / Engine Runtime Loading
```

이 방식을 통해 런타임에서는 복잡한 외부 모델 포맷을 직접 분석하지 않고, 사전에 정리된 바이너리 데이터를 빠르게 로딩할 수 있도록 했습니다.

---

### DirectX 11 렌더링 파이프라인

DirectX 11을 기반으로 렌더링 파이프라인을 직접 구성했습니다.

주요 구현 내용은 다음과 같습니다.

* Vertex Buffer / Index Buffer 기반 메시 렌더링
* Constant Buffer 기반 셰이더 파라미터 전달
* SRV 기반 텍스처 및 렌더 타깃 바인딩
* 머티리얼 단위 렌더링 제어
* 디퍼드 렌더링 파이프라인
* 후처리 렌더링 기반 구조
* 프러스텀 컬링 기반 비가시 오브젝트 제외

---

### 셰이더 리플렉션

셰이더에 정의된 상수 버퍼와 파라미터 정보를 런타임에서 읽어, 머티리얼 시스템과 툴 시스템에서 활용할 수 있도록 구현했습니다.

구현 목적은 다음과 같습니다.

* 셰이더 파라미터 자동 추출
* 머티리얼 편집 과정의 반복 작업 감소
* 코드 수정 없이 파라미터 확인 및 제어
* ImGui 디버그 패널과 연계한 런타임 값 확인

---

### SRV 기반 리소스 바인딩

DirectX 11의 Shader Resource View를 활용하여 텍스처, 렌더 타깃, 후처리 리소스를 셰이더에 전달하는 구조를 구현했습니다.

적용 예시는 다음과 같습니다.

* 머티리얼 텍스처 바인딩
* G-Buffer 리소스 참조
* UI 렌더링용 텍스처 참조
* 렌더 타깃 기반 효과 처리
* 구름 그림자 투영 효과

---

### UI 렌더링 시스템

렌더 타깃과 지오메트리 셰이더를 활용하여 UI 렌더링 시스템을 구현했습니다.

주요 구현 내용은 다음과 같습니다.

* 렌더 타깃 UV 절단을 통한 UI 표현
* 포인트 버퍼와 지오메트리 셰이더 연계를 통한 UI 출력
* 2D 트랜스폼 기반 UI 배치
* UI 오브젝트 계층 구조 처리

---

### NPC 상호작용 데이터 프레임워크

NPC 상호작용을 하드코딩하지 않고, 대화, 표정, 행동, 소리, 이펙트를 데이터 기반으로 동기화할 수 있도록 구성했습니다.

구현 목적은 다음과 같습니다.

* NPC 대화 흐름의 데이터화
* 대화 중 표정 상태 변경
* 대화 중 행동 이벤트 실행
* 대화 중 음성 및 효과음 재생
* 대화 중 이펙트 출력
* 콘텐츠 확장 시 코드 수정량 감소

---

### 타일 시스템

생활형 게임의 맵 구성을 위해 오토타일 및 타일별 상호작용 시스템을 구현했습니다.

## 렌더링 효과

### 렌더 타깃 투영 기반 구름 그림자

렌더 타깃을 활용하여 구름 그림자를 월드에 투영하는 방식으로 구현했습니다.
단순한 텍스처 오버레이가 아니라, 월드 좌표와 렌더 타깃 정보를 활용해 지형 위에 그림자가 반영되도록 구성했습니다.

---

### 둥근 지평선

버텍스 셰이더와 카메라 방향 내적을 활용하여, 지평선이 둥글게 말리는 듯한 시각 효과를 구현했습니다.
생활형 게임 특유의 축소된 행성감과 아기자기한 공간감을 표현하기 위한 렌더링 효과입니다.

---

### 컬러 팔레트 시스템

오브젝트의 색상 변형을 텍스처 자체를 여러 장 사용하는 방식이 아니라, 팔레트 데이터를 활용해 제어할 수 있도록 구현했습니다.

이를 통해 다음과 같은 효과를 기대했습니다.

* 색상 변형 리소스 수 감소
* 오브젝트 색상 커스터마이징
* 동일한 모델과 텍스처의 재사용성 증가

## 빌드 안내

1. Visual Studio 2022에서 솔루션 파일을 엽니다.
2. 플랫폼을 `x64`로 설정합니다.
3. `Engine` 프로젝트를 먼저 빌드합니다.
4. 실행 목적에 따라 `Client`, `MapEditor`, `ModelLoader` 중 하나를 시작 프로젝트로 설정합니다.
5. 빌드 후 실행합니다.

```text
Client      → 실제 게임 실행
MapEditor   → 맵 제작 툴 실행
ModelLoader → 외부 모델 리소스를 엔진 전용 바이너리 포맷으로 변환
```

외부 라이브러리 또는 리소스 경로가 로컬 환경에 맞게 설정되어 있어야 정상적으로 실행됩니다.

## 개발자 노트

이 프로젝트에서는 단순히 화면에 오브젝트를 출력하는 것보다, 게임 제작 과정에서 반복적으로 필요한 기반 구조를 직접 설계하는 데 중점을 두었습니다.

특히 컴포넌트 패턴, 빌더 패턴, 렌더링 패킷, 셰이더 리플렉션, ImGui 기반 제작 툴을 통해 오브젝트 생성, 렌더링, 디버깅, 맵 제작의 흐름을 분리하고 확장 가능한 구조로 구성하려고 했습니다.

또한 `ModelLoader`를 별도 프로젝트로 분리하여 외부 모델 데이터를 런타임에서 직접 처리하지 않고, `Engine`의 리소스 객체 체계에 맞는 바이너리 포맷으로 사전 변환하도록 구성했습니다. 이를 통해 리소스 로딩 비용을 줄이고, 런타임에서는 엔진이 기대하는 구조의 데이터를 일관되게 사용할 수 있도록 했습니다.

생활형 게임 특성에 맞춰 NPC 상호작용, 타일별 상호작용, 표정 상태, 구름 그림자, 둥근 지평선 등 콘텐츠와 렌더링 효과가 연결되는 구조도 구현했습니다.
